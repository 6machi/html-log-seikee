# 施策の地層メモ

## GitHub ver1

ファイル分割の骨組み版。構造はきれいだったが、単体HTML版で積み上げた施策が十分に移植できていなかった。
本番用ではなく、地層として残す。

## GitHub ver2

単体HTML版の機能を落とさないことを優先した移植版。
`index.html` は単体HTMLのまま。ファイル分割はまだしない。

### 引き継ぐべき施策

- v50系: ダイス結果の成功/失敗を分離しない
- v56系: 英数字の縦書き向け変換
- v59系: 同一話者の線を1本化する試み
- v60系: 読み込み時点での英数字変換
- v62系: 検索UI改善、バージョン表記
- v66以降: 本文欠け防止
- v70: 本文欠け対策を入れた確認用ベース

## 今後やるなら

1. まずver2の挙動を安定させる
2. テスト用ログで「文章が飛ばない」「読み込める」「印刷プレビューが出る」を確認
3. その後、`parser.js` / `normalize.js` / `layout.js` などに分割する


## GitHub ver3
- A5安定化を基準に、PDFセリフ1列の文字数初期値を32へ。
- 縦書きプレビュー上で本文・セリフ・ダイス枠を直接クリック編集できるようにした。
- GitHub ver2の単体HTML維持方針を継続。


## GitHub ver8

- ver7のボックステキスト実験で印刷ページ数が1170P化したため、ver3安定系へロールバック。
- PDFセリフ1列の初期値を37に変更。
- 39文字は欠けが確認されたため非推奨。
- 次にボックステキストを再挑戦する場合は、既存レイアウトを壊さない別ブランチで検証する。


## GitHub ver10
- A5安定系ver8をベースに、PC会話の罫線処理を調整。
- 同じ話者が連続する場合は発言を1ランに結合し、最初だけ話者名を表示。ページをまたぐ場合は続きの先頭に話者名を再表示。
- 話者が切り替わる場合は少し余白を入れつつ、会話グループ内の罫線はつながって見えるように調整。


## GitHub ver10
- ver9安定系をベースに、PC会話が連続している区間は話者が変わっても罫線を1本でつなぐ。
- 同じ話者ランの話者名省略・ページ頭での話者名再表示は維持。
- 間に本文・ダイスが入った場合は会話区間を切る。


## GitHub ver16

- ver10ベース。
- print用カラム内部に改行を残さず、splitTextForColumnsで行単位に分割。
- 1P文頭欠け（①zip / ②シーン一覧）対策。


## GitHub ver18
- ver17の英字横倒し調整を撤回。1d10等で半角dだけ目立つため、英数字は全角縦書きへ戻す。
- A5安定運用のため、PDF細部設定を画面から隠し、固定プリセット化。
